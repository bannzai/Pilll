- ドキュメント・コード上のコメント・データ構造・状態管理においてSingle State of Truthの考え方を適用する。同じ情報は2度書かないし、同じ物・同じ状態は2つ存在しないようにする

- 一覧・対応表・定数値など、コードを見ればわかる情報をコメントで繰り返さない
- ロジックについて、コメントには「何をしているか」は書かない
- 構造の定義について、「これは何を表現しているものか」を書く
- 中間表現の構造は作らない。ルール・理由・例は `coding-rules-no-intermediate-representations.md`（同ディレクトリ）を参照
